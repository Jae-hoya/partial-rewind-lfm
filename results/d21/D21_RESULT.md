- N1 은 라벨이 없으므로 이 수치들은 **양성률이지 위양성률이 아니다** (PREREG_D20 §6, R1-5). 이 재계수는 단위 문제만 다루며
  N1 안에 실제 모순이 섞였는지는 답하지 않는다.
- 군집이 15 개뿐이라 CI 는 넓다.

### B-6. 해석

1. **sufficient 개수와 W 분자는 어떤 처리에서도 바뀌지 않는다** (g₁ 3, MiniCheck 47; W 분자 2 / 34). D215 는 coverage 0·grounding 0 이라
   (a) 에서 이미 sufficient 가 아니기 때문이다. "빈 branch 가 sufficient 모집단을 오염시킨다"는 지적은 **분자에는 해당하지 않고**,
   W 의 **분모**에만 해당한다.
2. **W0.8 의 분모 효과**: 빈 branch 를 재실행 모집단에서 빼면(b) g₁ 0.50% → 0.77%, MiniCheck 8.50% → 13.13% [8.43, 18.92].
   기권으로 두고 분모에 남기면(c/c′) 원값 그대로다. 어느 쪽이 맞는지는 "빈 답 branch 의 재실행이 낭비인가"라는 정의 문제다 —
   비어 있던 branch 는 정의상 sufficient 가 아니므로 그 재실행은 낭비가 아니며, 분모에 남기는 (a)/(c) 가 `waste_by_query` 의 원 정의와 같다.
   (b) 는 "답이 있었던 branch 중 낭비 비율"이라는 다른 양이다. 두 양을 모두 보고하는 것이 안전하다.
3. **coverage 평균은 크게 바뀐다**: 0.427 → 0.665 (전 라운드), round 0 0.461 → 0.693. 즉 원 coverage 평균의 상당 부분은
   "답한 sub-question 이 인용을 못 단 것"이 아니라 "branch 전체가 기권한 것"에서 온다. (b)/(c)/(c′) 의 coverage 는 같은 값(D215 를 뺀 385 행)이다.
4. **grounding 평균도 바뀐다** (관례값 0 을 뺄 때만): g₁ 0.173 → 0.270, MiniCheck 0.476 → 0.741. g₁ 의 경우 빼더라도 0.27 수준이라
   "g₁ 이 근거를 못 본다"는 원고 결론은 처리와 무관하게 유지된다.
5. **verify 결론**: g₁ 은 모든 처리에서 0/150 (grounding 절 단독 통과는 최대 6). MiniCheck 은 (a)/(c) 0/150, (b)/(c′) 5/150 [1, 10].
   그 5 개는 1–3 개 branch 만 남은 round 다(B-4). "verification passes 0 in every config" 라는 문장은 빈 branch 를 검증에 포함하는 규칙
   (원 `lfm/verifier.py`) 아래에서만 참이며, 빈 branch 를 기권으로 빼는 규칙이면 MiniCheck 에서 5/150 이 된다 — 원고에 조건을 명시해야 한다.
6. 215 대 219 의 차이(추가 4 행)는 모든 지표에서 소수점 셋째 자리 수준이다 (coverage 0.665 vs 0.672, W 13.13% vs 13.28%).

### B-7. 한계

- 처리는 branch 단위로만 정의했다. 비어 있지 않은 branch 안의 빈 sub-answer 를 coverage 분모에서 빼는 sub-question 단위 기권은
  `waste_ratio.csv`·`results.json` 에 sub-answer 텍스트가 없어 계산하지 않았다 (사전 등록 한계). 그것을 하려면 캐시 재생이 필요하다.
- 두 실행은 같은 branch 산출물에 grounding 연산자만 다르게 적용한 것이며(행 단위 coverage·degraded·re_executed 동일 확인),
  MiniCheck 실행도 g₁ 실행의 재실행 궤적을 그대로 쓴다 — MiniCheck 가 검증을 통과시켰다면 달라졌을 이후 라운드는 반영되지 않는다.

  같은 3 단위 병기 + "positive rate, not false-positive rate". 단독 claim 포함 분모(43.7% / 37.9%)는 사후 추가이므로 병기 시 그렇게 밝힌다.
- R3: Table 1 근처에 (a)/(b)/(c′) 를 한 줄씩 추가하고, "verification passes 0/150" 에 "with empty branches included in the verification aggregate"
  조건을 붙인다. W0.8 은 원 정의(분모에 빈 branch 포함)를 주값으로 두고 (b) 를 민감도로 병기.
- :557 의 "mean coverage 0.474" 확인 필요 (50-토픽 round 0 은 0.461).
