### 1.2 PREREG_R2·DEVIATIONS와의 관계

- PREREG_R2 §9 표의 C 행("실시하지 않는다")은 DEVIATIONS 17에서 이미 바꿨다(2nd annotator 1차 라운드 A-v1, κ 0.024). §2는 **그 뒤의 2차 라운드이자 마지막 라운드**다. 1차 라운드는 실패한 라운드로 그대로 보고한다.
- §9의 κ 해석 규칙("κ ≥ 0.60이면 조정 라벨, 미달이면 라벨러별 결과와 '신뢰도 제한'")을 §2.7에서 따른다. 라벨러가 셋이 되었으므로 "κ ≥ 0.60"을 **저자–A와 저자–B 둘 다**로 읽는다(결정 3).
- R2의 E-R1 규칙 판정(DEVIATIONS 22: 발동)은 **바꾸지 않는다.** §3은 그 규칙의 사람 UA 다리보다 구체적인 검정(정답성·해악)을 더하고, §3.8 표가 원고 주결과 문구를 정한다(번복 경로 포함).
- §4는 PREREG_R2 §2~§8의 규칙을 코퍼스2에 그대로 옮긴다. 다른 점은 §4에 모두 적었다. PREREG_R2 §11의 "두 번째 코퍼스: 범위 밖" 행은 §4가 실행되면 대체된다.

### 1.3 이미 본 것 — 이 등록이 prospective가 아닌 이유

이 등록 전에 다음을 이미 봤다. 그래서 "prospective"라고 쓰지 않는다.
- R2 본실험 결과 전부(절감 L 0.086, E 0.028, 자동 비열등, H3~H5, E-R1 규칙 발동, DEVIATIONS 23의 0원 사후 분석).

  - §3 첫 표집안(토픽 층만, n = 45, seed 4401)을 미리 실행했다: **61문항, 답한 슬롯 E-SQ 37 / E-GR 14 / E-R1 37**, 답 평균 489자, 문항당 인용 청크(중복 제거) 토큰 평균 662 / 중앙값 437 / p90 1,423 / 최대 2,642(MiniCheck 토크나이저, 청크 전문 기준). **이 첫 안은 폐기했다(아래).**

**사후인 것, 공시한다.**
- §2 재측정 결정과 시트 장치(스크롤 관문, 체류, 번역 기록)는 A-v1의 실패 양상을 보고 정했다. 원고: "the first second-annotator round failed (κ = 0.02); we report it, and a second round with two new annotators, registered after observing that failure."
- §3 전체(R1-7 요구를 받은 뒤 R2 결과를 보고 설계).
- §4의 arm·지표·결정 규칙(R2 결과를 본 뒤 설계). **코퍼스2 데이터는 아직 내려받지 않았다.** 이것이 §4의 held-out 근거다.

**사후가 아닌 것.** κ 바 0.60(PREREG_R2 §9), 연산자 바 precision 0.85 / recall 0.70 / 회수 0.50과 탈락 정의(`SPEC_M1Vprime` §3·§4: **비가중 점추정과 Wilson 95% 상한**), §4의 판정 규칙(PREREG_R2 §5)은 이 문서에서 바꾸지 않는다. §2.7의 문구 행도 이 SPEC 정의(비가중 점추정, Wilson 상한)로 판정하고, Hájek 가중 추정은 함께 보고만 한다.

### 2.3 연습(3단계)과 해제

- 3단계 = 연습 10문항. 문항마다 (1) annotator가 라벨을 고르면 **첫 답이 잠긴다**, (2) **저자의 커밋된 라벨만** 보인다(해석·근거 문장·하이라이트 없음, 판단 기준 `RULES` 원문은 원래 화면에 있다), (3) "확인" 뒤 다음 문항.

2. **스크롤 관문.** 근거 상자 높이 고정(55vh, 내부 스크롤). `scrollTop + clientHeight ≥ scrollHeight − 4`에 한 번 도달하면 `scrolled_to_bottom = 1`. 근거가 상자에 다 들어가면 표시 즉시 1. §3에서는 **인용 청크 블록**이 대상이다.
3. **최소 체류.** **t_min(초) = min(120, 10 + tokens / 12).** tokens는 §2에서 `premise_lengths.csv`의 doc_tokens(MiniCheck 토크나이저), §3에서 화면에 보이는 인용 청크 본문(`_included_lengths`까지)의 MiniCheck 토큰 합. **탭이 보이는 동안의 시간(active)**으로 센다. 남은 시간을 버튼 위에 표시. 예: 300토큰 35초, 1,064토큰 99초, 1,320토큰 이상 120초.

   - 상한 120초 근거(판정자당 강제 체류 합, 2026-11-11 새 표집으로 다시 계산, 시험 빌드 `_meta_q.json`): 1단계 3문항 0.09시간(평균 113초), 2단계 73문항 1.27시간(평균 63초) → 1~2단계 **1.37시간**, 3단계 0.23시간(평균 83초), 4단계 1.08시간(평균 77초) → **약 2.68시간**. 판정자당 예산 약 6시간(§5.3 추정 약 5.54시간) 안에 들어가고, 긴 근거(≥ 2,073토큰, C50 14문항)에서 하한이 지나치게 길어 피로가 쌓이는 것을 줄이려고 120초로 정했다. 체류는 하한일 뿐 읽기 시간을 정하지 않는다.

**공시.** (1) 보정·연습 단계의 참조 라벨은 피드백을 띄우려고 HTML 안에 들어 있다(소스를 열면 볼 수 있다). 시험·본 단계의 저자 라벨·arm·cell은 HTML에 없다. (2) C50의 저자 라벨(2026-09-06·11-03)은 관문 없는 시트에서 달았고 A·B는 관문 시트에서 단다. 이 비대칭은 κ에 영향을 줄 수 있으나 분리할 수 없다 — 원고 한계 절에 적는다.

받은 CSV는 **수정 없이 먼저 커밋**한다(SHA-256). 시간·스크롤 값으로 문항을 빼지 않는다(민감도만).

### 2.5 신뢰도 분석 (`experiments/r3_reliability.py`, C0에 커밋, 고치지 않고 실행)

| 세트 | 라벨러 | 역할 |
|---|---|---|
| **C50** | 저자 vs A, 저자 vs B | **1차(판정).** |
| C50 | A vs B, 3인 Fleiss κ | 함께 보고(판정에 쓰지 않음) |
| C50-v1 | 저자 vs A-v1 | 기존 결과(κ 0.024). 실패한 1차 라운드로 그대로 다시 보고 |
| C50 | A-v1 vs A, A-v1 vs B | 기술 통계 |
| P10 | 저자 vs A, 저자 vs B (첫 답) | 연습 일치(피드백 중 측정, 추정에 넣지 않음) |

- **라벨**: 1차는 최종 `label`. `first_label` κ는 민감도.
- **1차 지표는 이진**(지지 = 1, 불지지·판단불가 = 0) **비가중 Cohen κ** = (p_o − p_e)/(1 − p_e), p_e = Σ_k p_{1k} p_{2k}.
- **함께 보고(판정에 쓰지 않음)**: Fleiss κ(3인), Hájek 가중 κ(w = N_h/n_h, C50 n_h = 13/21/12/4, N_h = 37/171/77/9로 p_o와 주변 비율 계산), 3범주 κ, PABAK = 2p_o − 1(K범주면 (K·p_o − 1)/(K − 1)), Gwet AC1 = (p_o − p_e^γ)/(1 − p_e^γ), p_e^γ = (1/(K−1)) Σ_k π_k(1 − π_k), π_k = (p_{1k} + p_{2k})/2 — **AC1과 PABAK은 쌍별로만**(저자–A, 저자–B, A–B) 내고, 3인 통계는 Fleiss κ 하나다, 일치율, 각 라벨러의 '지지' 비율, 2×2(3×3) 표 전체.
- **CI**: cell 층화 문항 부트스트랩(cell 안 복원 재추출), B = 10,000, seed 4310, 백분위 95%. **판정 문구 옆에 항상 95% CI를 적는다.**
- **판정**: 저자–A **그리고** 저자–B 이진 비가중 κ 점추정 ≥ 0.60 → "신뢰도 확보". 하나라도 미달 → "신뢰도 제한". **PABAK·AC1이 0.60을 넘어도 등급을 바꾸지 않는다**(V′ '지지' 비율 약 0.8이라 κ가 낮게 나오는 것을 미리 예상하고 공시한다). 원고: "point-estimate bar, 95% CI reported; the study is not powered for a CI-based bar" (n = 50, 유병률 약 0.8이면 반폭 약 ±0.25).
- **장치 진단(모두 보고, 제외 없음)**: 길이 구간별 일치와 κ(경계 613 / 2,073 = 294 모집단 doc_tokens 정렬 index 98·196; C50은 짧은 20 / 중간 16 / 긴 14 — A-v1의 9/17·3/17·0/16은 C50 자체 3분위였으므로 A-v1도 이 경계로 '지지' 수, 이진 일치율, 이진 κ를 다시 계산해 나란히 낸다), 길이 구간별 active_ms 중앙값, active_ms/t_min 분포, 번역 범주별 일치, hidden_ms > active_ms 문항 수.
- **민감도(1차 표에 함께 올린다)**: (1) active_ms < 1.2 · t_min · 1000 문항 제외, (2) translator_used = 근거 전체 제외, (3) `first_label`.

### 2.6 조정 (기계적 다수결, 논의 없음)

- **조정 라벨** = 저자·A·B 이진 라벨(지지 vs 불지지 ∪ 판단불가)의 다수결. 라벨러가 셋이라 항상 정해진다. 3범주 조정 라벨은 만들지 않는다.
- 아무도 논의하지 않는다. 저자는 A·B 라벨을 보고 자기 라벨을 바꾸지 않는다.
- **보고**: 저자 라벨이 다수결에서 뒤집힌 문항 수(지지 → 불지지, 불지지 → 지지), A·B가 각각 소수였던 문항 수, 세 명 만장일치 비율, 뒤집힘을 길이 구간으로 나눈 표와 번역 범주로 나눈 표(번역 범주 = 그 문항에서 A가 고른 `translator_used`, B가 고른 `translator_used`를 판정자별로 따로). 저자가 소수로 뒤집힌 문항이 0이면 "the majority coincided with the author on every item"이라고 그대로 적는다.
- 조정 라벨에 대한 κ는 계산하지 않는다(조정 라벨은 신뢰도 근거가 아니라 참조 라벨의 개선판이다).
- A·B 중 한 명만 완료하면 다수결을 만들지 않는다(§1.1 "single second annotator").

### 2.7 연산자 precision / recall

**연산자.** MiniCheck-Flan-T5-Large 단일 문서, p > 0.5. 점수열 = `registered_dup` 전제의 p_mc_new(`rescore_singledoc_rows.csv`). dedup 전제(`VPRIME_DEDUP_CHECK.json`)를 공동 보고, g1(p_g1 ≥ 0.5)을 같은 표에 둔다.

**정의** (y = 사람 지지, m = 연산자 지지).
- **판정에 쓰는 추정(SPEC_M1Vprime §3·§4와 같다): 비가중 비율과 Wilson 95% 구간.** precision = #[m=1 ∧ y=1]/#[m=1]; recall = #[m=1 ∧ y=1]/#[y=1]; 회수 = g1 비지지 ∧ y=1 중 m=1 비율. 아래 문구 행의 "점추정"은 이 비가중 비율, "상한"은 Wilson 95% 상한이다.
- **함께 보고(판정에 쓰지 않음): Hájek 가중 추정**(w_i = N_h/n_h, `vprime_final_score.py`의 가중 방식과 같다; precision = Σw[m=1 ∧ y=1]/Σw[m=1] 등)과 그 CI(cell 층화 부트스트랩, B = 10,000, seed 4311, 백분위 95%). 같은 문구 규칙을 가중 점추정·부트스트랩 상한에 적용한 행도 "가중 기준이면 행 k"로 옆에 적는다.
- 이것이 §1.3("연산자 바와 탈락 정의는 바꾸지 않는다")과 맞는 유일한 읽기다. **V1 재진술**: 비가중 0.861 / 0.756 ≥ 0.85 / 0.70 → 행 1(등록 규칙대로 통과). 가중 0.850(0.8499) / 0.782는 가중 기준이면 precision이 행 2 — `VPRIME_FINAL.md`가 이미 "바와 같다"고 밝힌 그대로 함께 적는다. `r3_reliability.py --selftest`가 V1 = 행 1을 assert한다.

| 판 | 문항 | 라벨 | n_h |
|---|---|---|---|
| V1 등록판 | V′ 100 | 저자(`VPRIME_FINAL`: 0.861/0.756, 가중 0.850/0.782). 그대로 다시 적는다 | 25/42/25/8 |
| V1c | C50 | 저자 | 13/21/12/4 |
| V3a | C50 | A | 같음 |
| V3b | C50 | B | 같음 |
| **V4** | C50 | 기계적 다수결 | 같음 |
| V5 | V′ 100 | C50은 다수결, 나머지 50은 저자 | 25/42/25/8 |

**1차 판 (결정 3).**
- 저자–A κ ≥ 0.60 **그리고** 저자–B κ ≥ 0.60 → **V4가 1차.**
- 그 밖 → **V1c, V3a, V3b를 나란히 1차**로 내고 V4를 함께 둔다(전부 "reliability-limited" 표시). 문구 규칙은 **세 라벨러 판(V1c, V3a, V3b) 중 가장 나쁜 행**으로 적용한다.
- 한 명만 완료하면 V1c와 그 사람의 V3를 나란히 1차, 더 나쁜 행.

**선택은 다시 열지 않는다.** MiniCheck 선택은 V1(등록된 2단계 규칙)로 이미 내렸다. R2 컨트롤러가 이 연산자로 결정했으므로 바꾸면 재실행이 필요하고, 사후 재선택은 사후 재측정보다 나쁘다. 1차 판은 **타당도 근거**로만 쓰고 원고 문구만 정한다.

| 행 | 조건 (precision, recall 각각) | 원고 문구 |
|---|---|---|
| 3 (우선) | 점추정 < 바 − 0.10 (P < 0.75 또는 R < 0.60) **또는** SPEC §4 탈락(점추정 < 바 ∧ Wilson 95% 상한 < 바) | "validity not confirmed by independent annotators." 초록과 X에 적고, 연산자에 기대는 결과(R2 grounding 다리, 사람 UA의 "모든 문장 MiniCheck 지지" 조건)에 단서를 붙인다. 토큰 절감은 연산자 판정에 의존하지만 회계 자체는 영향받지 않는다고 따로 적는다. 재선택·재실행 없음 |
| 2 | 바 − 0.10 ≤ 점추정 < 바 | "below the bar on [majority / per-annotator] labels but within uncertainty; selection stands as registered" — 괄호는 채점 코드가 1차 판에서 채운다(V4 → "majority", V1c·V3 → "per-annotator") |
| 1 | 점추정 ≥ 바 (0.85 / 0.70) | "confirmed on majority labels of three annotators" (신뢰도 제한이면 "on each annotator's labels") |

- 우선순위: 3 > 2 > 1. precision과 recall이 다른 행에 걸리면 **더 나쁜 행**을 따른다.
- 회수(바 0.50)는 모든 판에서 보고하되 문구 규칙에는 넣지 않는다.
- 신뢰도 제한이면 문구 앞에 "reliability-limited"를 붙인다.
- **표본 한계(공시)**: n = 50이라 precision·recall CI가 넓다. V1(n = 100)과 같은 바와 같은 규칙(비가중 점추정, 탈락 조건만 Wilson 상한)을 쓴다.

**범위 밖, 응답서에 별도 행.** H2-A 앵커 25(κ 0.053)와 H3~H5의 A·B 척도 라벨은 다시 라벨하지 않는다. 응답서에 "single-annotator or reliability-limited; not re-labeled"로 한 줄씩 적는다.

### 3.3 표집

**두 방향 층(2026-11-11 변경, §1.3).** 슬롯마다 g = 1[E-GR이 그 슬롯에 비어 있지 않은 답을 냈다]. U_E 357슬롯 = g1 126(24토픽) + g0 231(28토픽). 슬롯당 서로 다른 답 수 평균은 g1 1.984, g0 1.065다(g1 슬롯은 E-GR 답이 라운드 0 답과 달라 문항이 두 배 가까이 된다). **이 수와 아래 배분은 답 개수만으로 정했고 라벨은 하나도 없을 때다.**
- **층(44개)**:
  - g1 × 토픽: 24층(`g1|t000` …), N_h = 그 토픽의 g1 슬롯 수(1~11).
  - g0 × 토픽: N_h(그 토픽의 g0 슬롯 수) ≥ 5인 토픽 19개는 토픽마다 한 층(`g0|t000` …). **N_h ≤ 4인 토픽 9개(21슬롯: t004, t011, t012, t015, t019, t023, t024, t025, t027)는 한 층 `g0|small`로 묶는다.**
- **왜 묶는가(주 세션 지시와 다른 점, 공시).** 지시는 "층 = (g) × 토픽"이었다. 모든 층에 n_h ≥ 1을 두면(Hájek 불편성의 조건) 최소 24 + 28 = 52슬롯, 기대 약 77문항(g1 25면 약 79)으로 본 문항 상한 70을 넘는다. 그래서 g1은 토픽 층을 그대로 두고, g0만 작은 토픽을 한 층으로 묶었다. **묶음 한계 규칙(정확히 이대로)**: g0 토픽 가운데 N_h ≤ k인 토픽을 묶을 때, 기대 본 문항(층별 슬롯당 서로 다른 답 수 평균 × n_h의 합)이 **70보다 작은 가장 작은 정수 k**를 쓴다. seed 4401 실제 추출도 70 이하여야 하고, 아니면 멈추고 보고한다. 한계별 기대 문항: k = 0 77.3, 1 76.3, 2 73.3, 3 70.3, **4 69.3** → **K_SMALL = 4**(실제 69문항 ≤ 70). 생성기가 k = 0…4를 다시 계산해 이 규칙을 assert한다. 개수만 본 결정이다. 공시: 이 규칙을 적기 전에 한계 5(기대 67.1, 실제 71 > 70 → 쓰지 않음)와 6(기대 65.0, 실제 64)을 먼저 시도했고, C0 전 초안에 한계 6을 "가장 작은 한계"라고 잘못 적었다. 재감사에서 규칙의 답이 4임이 드러나 4로 바꿨다(C0 전, 라벨 0개; C0 전 수정 기록).
- **배분**: g1은 n = **25**를 24층에 √N 배분(아래 알고리즘) → n_h = 1인 층 23개, 2인 층 1개(`g1|t036`). g0은 20층에 층마다 **1**(합 20). 합 **45슬롯**.
- **√N 배분 알고리즘(정확히 이대로; `r2_sheets.allocate`는 비례 배분이라 쓰지 않는다)**: raw_h = n · √N_h / Σ√N_h; n_h = max(1, min(N_h, ⌊raw_h⌋)); 합이 n보다 작으면 n_h < N_h인 층 중 (raw_h − n_h)가 큰 순(동점은 층 id 사전순)으로 1씩 더한다; 합이 n보다 크면 n_h > 1인 층 중 (raw_h − n_h)가 작은 순으로 1씩 뺀다(`r3_sheet.sqrt_alloc`).
- **추출**: `numpy.default_rng(4401)` 하나로, 층 id 사전순(`g0|small`, `g0|t000`, …, `g1|t000`, …)으로 층마다 `rng.permutation(N_h)[:n_h]`, 색인 정렬. 층 안 후보 순서 = (seed, query_id, branch, sq_index) 정렬. **가중 w = N_h/n_h (층 = (g, 토픽) 칸 또는 `g0|small`)**. 층별 Σw = N_h이므로 Σw = 357.
- **예상 문항**: 층별 슬롯당 서로 다른 답 수 평균으로 **69.3**(69.31), 이 규칙으로 미리 실행한 결과 **45슬롯 / 69문항, 답한 슬롯 E-SQ 29 / E-GR 25 / E-R1 30**. 생성기는 묶음 한계 규칙(K_SMALL = 4), 층 수 44(g1 24 / g0 20, `g0|small` N = 21), 배분, 기대 69.31, 69문항(≤ 70), 답한 슬롯 수를 assert한다. C1이 다르면 멈추고 원인을 적는다. 실제 수는 `_meta_q.json`에 기록(`expected_items_by_pool_limit` 포함). 2단계 = 본 69 + 점검 4 = **73문항**.
- **H4 겹침**: H4 36문항과 글자가 같은 문항을 `sealed/_note_overlap.json`에 적고 포함·제외로 보고(시험 빌드 8문항).
- **검정력 주(공시, 라벨 없이 가정으로만).** assay 관문의 G_GR = E_w[S_GR − 2]는 g0 슬롯에서 정확히 0이므로 g1 슬롯에서만 정보가 온다. E-GR 답의 (S − 2)가 평균 μ, 표준편차 sd라고 **가정**하고(m_GR = 2 + μ는 아직 아무도 보지 않았다) 두 설계를 반복 추출해 G_GR의 설계 표준편차를 구했다(관문 통과 확률 ≈ Φ(E[G]/SD − 1.645)):

### 3.4 루브릭 (`results/r3/sheets/` HTML 첫 화면·각 문항 위, 한국어 + 영어 앵커)

판정자는 문항마다 **C(정답성)**와 **K(완전성)**를 독립으로 고른다. 기준은 **보여 준 컨텍스트뿐**이다. 바깥 지식으로 맞아 보여도 컨텍스트에 없으면 "C1 미지지"다. 안내문은 비전문가용으로 청크(근거 글 조각), 컨텍스트(모델이 받은 청크 전부), 인용(답의 [1][2]가 가리키는 청크)을 한 줄씩 정의한다. 원고에는 "evidence-grounded (attributable) correctness, judged against the retrieved context the system saw; not world-fact correctness"라고 쓴다.

**C — 근거 대비 정답성**

| 값 | 기준 |
|---|---|
| C2a 지지(인용) | 모든 사실 주장이 **답이 인용한 청크**에서 확인된다. 요약·바꿔 쓰기 허용 |
| C2b 지지(다른 청크) | 모든 주장이 컨텍스트에서 확인되지만 적어도 하나는 **인용하지 않은** 청크에서만 확인된다 |
| C1 미지지 | 적어도 한 주장이 컨텍스트 어디에서도 확인되지 않는다(모순은 아님) |
| C0 오류 | 적어도 한 주장이 컨텍스트와 **모순**된다(숫자·날짜·이름·주체·인과), 또는 다른 대상에 대한 근거를 그 대상인 양 썼다 |

"사실 주장" = 참·거짓을 따질 수 있는 문장·절. 연결어, 질문 되풀이, "근거에 따르면" 같은 틀 문장은 세지 않는다. S 계산에서 C2a·C2b는 같은 C2다. 인용 정확도(C2a/(C2a+C2b))는 보고만 한다.

**K — 질문 대비 완전성**: K2 완전(모든 부분에 직접 답) / K1 부분(일부만, 또는 간접·일반적) / K0 비응답(다른 주제, 회피, 배경만). 안내문에 가상 예시를 둔다: C2a·K2, C2b, **C1과 C0의 차이**(값이 컨텍스트 어디에도 없으면 C1, 다른 값이 적혀 있으면 C0), K1, **K0**(배경만 말하는 답).

**"컨텍스트에 X가 없다"고 말하는 답(안내문 예시로 고정).** "주어진 자료에는 X가 나오지 않는다" 같은 문장은 컨텍스트에 대한 말이라 **사실 주장으로 세지 않는다**(위 틀 문장과 같다). 답이 그것뿐이면 **C2a · K0**(S = 2, 기권과 같은 점수)다 — 실제로 컨텍스트에 X가 있어도 K0다(답하지 않았으므로). 다른 사실 주장이 함께 있으면 C는 그 주장들로, K는 질문에 답한 정도로 정한다. 이 규칙은 루브릭에 없던 경우를 정하는 절차 보충이고 C0 전에 정했다.

**슬롯 점수 S (채점 코드가 결정론적으로 매긴다)**

| S | 조건 |
|---|---|
| 0 | 답함 ∧ C0 (해악) |
| 1 | 답함 ∧ C1 (해악) |
| 2 | **기권(빈 답)**, 또는 답함 ∧ C2 ∧ K0 |
| 3 | 답함 ∧ C2 ∧ K1 |
| 4 | 답함 ∧ C2 ∧ K2 |

해악 H = 1[답함 ∧ C ≤ 1].

**기권 처리.** 1차는 **S = 2 고정, 라벨하지 않는다.** 민감도 S = 1, S = 3을 함께 낸다. 기권 점수를 s_abst라 쓴다. **s_abst는 G·F의 기준인 '전부 기권하는 arm A0'의 점수이기도 하므로, 민감도 판에서는 G와 F의 기준값도 같은 s_abst(1 또는 3)로 바꾼다**(§3.7). 그러면 G(s) = G(2) − (s − 2)·π_GR, F_c(s) = F_c(2) − (s − 2)·(π_a − 0.5·π_GR)이다(π = 그 arm이 답한 슬롯의 가중 비율). U_E에서 π_a(E-SQ 277/357, E-R1 269/357)가 0.5·π_GR(0.5 × 126/357)보다 훨씬 크고, D_c도 a만 답한 슬롯(E-SQ 193, E-R1 184)이 E-GR만 답한 슬롯(42, 41)보다 많아 s가 클수록 작아진다. 그래서 **S = 3이 E-SQ·E-R1 비열등에 가장 불리한 경계**(기권이 더 많은 E-GR을 유리하게 함)이고 assay 관문에도 가장 엄한 경계다. 이를 1차 옆에 적는다. 참고: H5(동료) E-SQ 최종 기권 30 중 답있음 2(0.067). E-GR·E-R1 기권에는 해당 자료가 없다고 적는다.

- **공시(점검 토픽 비대칭).** 2단계에서 dev 토픽은 점검으로만 나온다: t007은 점검 3개에 본 문항 0개, t037은 점검 1개뿐이다. 본 문항에도 한 문항만 나오는 held-out 토픽이 4개(t019, t023, t027, t051, 시험 빌드) 있어 '토픽에 문항 하나'만으로 점검이 드러나지는 않지만, 본 문항 없이 세 번 나오는 t007은 눈에 띌 수 있다 — 점검 통과율을 이 점과 함께 읽는다.
- **통과 = 3/4 이상.** 쉬운·어려운 결과를 따로 보고한다(어려운 2개를 모두 놓치면 통과할 수 없다).
- dev 토픽에서 만든 문항이라 분포가 다르다는 점을 공시한다.

| 점검 결과 | 1차 판정 근거 | R1-7 문구 |
|---|---|---|
| A·B 둘 다 통과, κ_w(S) ≥ 0.40 | 판정자별 분석 둘 다(§3.7 판정자 결합) | 충족 |

### 3.7 분석 (`r3_quality_score.py`)

**표기.** 판정자 j, 슬롯 i, arm a의 점수 S_ai, 해악 H_ai. 비교 c: a ∈ {E-SQ, E-R1} 대 E-GR. 모든 합은 표본 슬롯에 대해 w_i = N_h/n_h로 가중한 Hájek 평균 E_w[·] = Σw_i(·)/Σw_i (U_E 기준).

- G_GR = E_w[S_GR − s_abst] — E-GR이 "전부 기권하는 가상 arm A0"(모든 슬롯 점수 = 기권 점수 s_abst)보다 나은 정도. **s_abst = 2(1차)**; 보조 2의 민감도에서는 s_abst = 1 / 3을 S 배열과 G·F 기준에 똑같이 쓴다(§3.4). D·ΔH는 s_abst와 기준이 무관하다.
- D_c = E_w[S_a − S_GR] — 절대 점수 차.
- **F_c = E_w[(S_a − s_abst) − 0.5 · (S_GR − s_abst)]**(1차 s_abst = 2) — a가 A0 대비 E-GR 효과의 **50% 이상을 보존**하는가(상대 마진).
- ΔH_c = E_w[H_a − H_GR].

**부트스트랩.** B = 10,000, seed **4410**. **표본에 나타난 토픽**(등록 추출에서 **26개**)을 군집으로 복원 재추출하고, 뽑힌 토픽마다 **그 토픽 안의 층별로**(g1|토픽, g0|토픽, 그리고 `g0|small` 슬롯 가운데 그 토픽에 속한 것) 표본 슬롯을 같은 수만큼 복원 재추출한 뒤, 고정 가중 w = N_h/n_h로 Hájek을 다시 계산한다(한 칸에 슬롯이 1개면 토픽 단계에서만 변동). 같은 재추출 색인을 두 비교와 두 판정자에 쓴다. 판정은 백분위 90% CI, 95% CI도 보고한다. seed 단계는 두지 않는다(seed는 표집 단계가 아니다). 공시: `g0|small`은 9토픽에 걸친 한 층이라 그 한 슬롯(등록 추출 t019, w = 21)은 그 슬롯의 토픽이 뽑힐 때만 들어간다 — 층 구조를 근사하는 부트스트랩이다. U_E 28토픽 가운데 **t011·t012**는 g1 슬롯이 없고 g0 N_h ≤ 4라 `g0|small` 안에만 있으며 이 추출에서 뽑히지 않았다. 두 토픽은 표본과 부트스트랩 군집에 없고, `g0|small`의 한 슬롯(가중 21)을 통해서만 대표된다.

**3단계 뒤 2단계 저장(§2.4).** 판정자마다 3단계가 처음 보인 시각 뒤에 `answered_at_iso`가 찍힌 2단계 행의 수를 보고한다. 그런 행은 1차 분석에서 `first_C`·`first_K`를 쓴다(시트가 막으므로 기대 0). 공시: CSV에는 첫 답과 마지막 답만 있으므로 대체 값은 '3단계 전 마지막 답'이 아니라 **첫 답**이다 — 그 행에서는 3단계 전에 한 정당한 2단계 수정도 함께 되돌려진다.

**P1 (1차) — 점수, 상대 마진.**
1. **검정 민감도(assay) 관문**: G_GR의 90% 하한 > 0이 아니면 P1 = "결론 없음(검정 민감도 부족)". E-GR이 기권보다 낫다는 것을 보이지 못하면 비열등을 말할 수 없다. (표본 E-GR 답 25슬롯으로 과표집했지만 §3.3 검정력 주의 가정에 따라 관문 통과 확률은 약 0.5~1.0 — 이 결과가 나올 가능성을 미리 적는다.)
2. 관문 통과 시: F_c 90% 하한 > 0 → **비열등**, F_c 90% 상한 < 0 → **열등**, 그 밖 → **결론 없음**.

*왜 절대 마진이 아닌가*: E-GR은 U_E의 약 35%(126/357)에서만 답한다. 전부 기권하는 A0의 D = −0.35 · (m_GR − 2)이므로 m_GR ≤ 3.4이면 A0가 절대 δ = 0.5를 통과한다. 전체 슬롯 기준 이진 지표(S = 4 비율, δ = 0.10)에서는 E-GR의 S = 4 비율 자체가 약 0.04 수준이라 A0가 더 쉽게 통과한다. 상대 마진과 assay 관문은 라벨 전에 고정할 수 있고 이 문제가 없다. 0.5(50% 보존)는 비열등 설계의 통상 관례이고 데이터를 보고 고른 값이 아니다.

**P2 (공동 1차) — 해악.** ΔH 90% 상한 < +0.10 → 비열등; 90% 하한 > +0.10 → 열등; 그 밖 → 결론 없음. (+0.10 = 정보 슬롯 10개당 틀리거나 근거 없는 답 1개 증가.) A0는 ΔH ≤ 0이라 P2는 자명하게 통과하므로 assay 관문은 P1에만 둔다.

**판정자 결합.** 다리(P1, P2)마다 유효 판정자 둘이 같은 판정이면 그 판정, 다르면 "결론 없음".

**신뢰도 문턱.** 두 유효 판정자의 답한 문항(점검·보정 제외)에서 S의 이차 가중 κ_w < 0.40이면 **비열등 판정은 "결론 없음(신뢰도 부족)"으로 강제**한다(차등 없는 오분류는 짝 차이를 0 쪽으로 줄여 비열등을 쉽게 만들기 때문). 열등 판정은 강제하지 않는다. 유효 판정자가 1명이면 판정은 하되 "single judge, reliability not estimable"로 적는다.

**보조 (모두 보고, 판정에 쓰지 않음).**
1. 절대 D (δ ∈ {0.25, 0.5, 1.0}), 이진 S = 4 비율 차(U_E 기준 δ 0.10, 전체 환산 함께), ΔH 민감도 +0.05.
2. 기권 S = 1, S = 3(가장 보수적 경계)으로 P1·P2 재판정. G·F의 A0 기준도 같은 s_abst(1 / 3)를 쓴다: G = E_w[S_GR − s_abst], F_c = E_w[(S_a − s_abst) − 0.5 (S_GR − s_abst)](`r3_quality_score.stats_of(…, s_abst)`).
3. 조건부 품질: 두 arm 모두 답한 슬롯의 D(동일 텍스트 짝 포함·제외), arm별 C·K 분포, m_GR(E-GR 답한 문항의 평균 S) 판정자별.
4. **E-R1은 답했고 E-GR은 기권한 슬롯에서 E-R1 답의 C 분포** — "GR이 버린 라운드 0 답이 틀렸는가"를 직접 보인다.
5. 토픽 1단·seed별 점추정과 부호표, t000~t004 제외 판.
6. H4 겹침 제외, 20초 미만 문항 제외, active_ms < 1.2 · t_min 제외, 번역 "근거 전체" 제외.
7. paraphrase 문항 제외(produced_round ≥ 1 ∧ asked ≠ 원래 질문). 원래 문구로 보이므로 GR의 K가 불리할 수 있다 — 방향을 공시.
8. 질의 수준: 질의·seed당 S = 4 sub-answer 수 Q_a = (Σw / 전체 질의·seed 수) × E_w[1(S_a = 4)]의 arm별 추정과 **차이 Q_a − Q_GR**(같은 부트스트랩 색인으로 90%·95% CI). 전체 질의·seed 수는 생성기가 `_meta_q.json`의 `n_query_seeds_all`(= 35 × 3 = 105)에 쓰고 채점 코드가 읽는다(숫자를 코드에 박지 않는다). U_E 밖 슬롯은 모두 기권이라 S = 4가 0이다.
9. **기계적 합의 판**: 두 판정자 S의 최솟값(보수적)과 평균으로 P1·P2를 다시 낸다. 논의 기반 조정은 하지 않는다(§3.9).
10. "나머지 컨텍스트" 펼침(§2.4 7): 판정자별 펼친 문항 수, 펼친 문항·안 펼친 문항의 C2b 수.
11. 50문항·69문항을 다 채우지 못한 판정자는 판정에 넣지 않고 단 문항 수를 보고한다(§7.3).

**판정자 간 일치(답한 문항, 점검·보정 제외).** S: 이차 가중 κ_w(문턱에 쓰는 값), Gwet AC2, 정확·±1 일치율, 혼동표. C·K: 선형 가중 κ. 해악 경계(C ≤ 1 vs C2) Cohen κ. **κ_w(S)의 95% CI: 위 부트스트랩과 같은 두 단 방식(토픽 → 토픽 안 층별 슬롯), 뽑힌 슬롯의 답한 문항(슬롯 안 같은 글은 한 문항)을 모아 κ_w를 다시 계산, B = 10,000, seed 4411**(§8). (ICC는 내지 않는다.)

## 4. 두 번째 코퍼스 라이브 재현 (R2-8)

### 4.1 성격

- R2 결과를 모두 본 뒤 설계했다. "**코퍼스2에 대해 결과를 보기 전에 등록한 재현**"이라고 쓴다.

- 토픽 승인은 코퍼스1처럼 위임·자동 기계 검사다(`approval.mode: delegated`). 원고: "automated, criteria-based topic approval; no human curation" (두 코퍼스 모두).

### 4.2 코퍼스와 토픽

**1순위: arXiv 제목 + 초록.** 위키백과(백과사전식)와 장르·용어 밀도·문서 구조가 다르다.

**라이선스 관문 C-L (다운로드 직후, 생성 전).** 아직 확인하지 않았다. `MANIFEST_C2.json`에 출처 URL, 확인 일시, 데이터셋 revision 해시를 적는다.
- 1순위 원천: HF 미러 `librarian-bots/arxiv-metadata-snapshot`(카드 cc0-1.0, **매주 동기화 → revision 해시 고정 필수**), 대안 `gfissore/arxiv-abstracts-2021`(카드 cc0-1.0, 2021년까지). parquet 미러를 우선한다.
- 받아들이는 조건: arXiv 공식 문서에서 **메타데이터(초록 포함)가 CC0**임을 C-L 시점에 확인. 데이터셋의 문서별 `license` 필드는 **본문 라이선스이지 메타데이터 라이선스가 아니다** — MANIFEST에 적는다.
- 확인하지 못하면 §4.2.1 대체 코퍼스로 내려간다. 그것도 확인하지 못하면 실행하지 않고 "claims restricted to the evaluated corpus"를 유지한다.

**코퍼스 구성** (`data_c2/download_c2.py`, seed **4500**): arXiv id 최신 버전 한 행 → 초록 400자 미만·"withdrawn"으로 시작·제목/초록 빈 행 제외 → **150,000건** 단순 무작위 → archive 분포를 MANIFEST에.

**필드 대응** (코퍼스1 스키마, `chunk_index.py`·`topics.py`·`heldout.py`를 그대로 쓰려고)
- `identifier`: arXiv id 사전순 1부터 정수(`data_c2/id_map.parquet`). chunk_id `d{n}s0p0`이 `CITATION_RE`를 통과.
- `name` 제목, `url` `https://arxiv.org/abs/{id}`, `abstract` 초록(공백만 정규화, LaTeX 그대로).
- `sections`: `[{"type":"section","name":"Abstract","has_parts":[{"type":"paragraph","value":초록}]}]` — `chunk_index.py:136`은 sections만 청킹하므로 초록을 여기에 넣는다. 문서 1개 = 청크 1개.

#### 4.2.1 대체 코퍼스와 파일럿 전환 규칙 (결과 지표와 무관)

- **대체 코퍼스(2순위)**: PubMed Central Open Access 상업 이용 가능 부분집합에서 문서별 license가 CC0 또는 CC BY인 논문만. 섹션 구조가 있는 본문(`sections` = JATS 본문 절, `abstract` = 초록, `infoboxes` = JATS `subj-group` 주제, archive 대응 = 최상위 주제 그룹). 표집 150,000건(seed **4510**), 같은 규칙. 필드 대응의 세부 차이는 이탈로 기록하고 규칙은 그대로 둔다. 어댑터 코드는 전환이 일어날 때만 쓴다(규칙은 지금 고정).
- **전환 규칙(한 번만)**: 1순위 pilot3(s1)에서 다음 중 하나면 대체 코퍼스로 바꾸고 pilot3를 다시 돈다.
  - (a) E-GR 라운드 0 answered(비기권) sub-answer 비율 < 0.05 (퇴화)
  - (b) 라이선스 관문 C-L 실패
  - **L-BR의 FREEZE 사건 0회는 단독으로 전환을 일으키지 않는다(결정).** (a)와 함께 일어나면 전환 사유에 공동 원인으로 적는다. FREEZE 0회가 단독이면 전환하지 않고 1순위로 본실험을 진행하며, 본실험에서도 0회면 C-H1을 "재현 실패(원인: sufficient branch 없음)"로 적는다. 공시: 이 결정으로 FREEZE 조건은 (a)가 이미 발동시키는 경우에만 의미가 있어 독립 효과가 없다. 3토픽 × 1 seed의 우연한 0회로 하루짜리 어댑터 작업이 일어나는 것을 막으려는 것이다.
- 대체 코퍼스도 (a)에 걸리면 **1순위 코퍼스로 본실험을 돌리고** 해당 가설을 "판정 불가"로 보고한다(라이선스 실패면 실행하지 않는다). 이 점검은 절감·비열등 결과를 보지 않는다.
- **일정 공시**: 대체 코퍼스 전환이 일어나면 2일 일정 안에 §4를 끝낼 수 없다. 그 경우 §7.3에 따라 §4 본실험 완료 시점을 DEVIATIONS에 적고, 원고는 §4 결과 없이 내지 않는다(교신저자 결정 대기 항목으로 보고).

### 4.8 분석과 가설

**코드.** 래퍼 `experiments/c2_analyze.py`가 `r2_analyze.analyze()`를 **바꾸지 않고** 부른다(`r2_analyze.py` `git diff` 없음). 코퍼스에 묶인 다섯 군데만 래퍼에서 바꾼다(모듈 속성 교체, 실행 뒤 원복): `--rescore`의 연산자 설정과 청크 본문(`config_c2.yaml`·`data_c2/index`), C-G4 외삽 기본값(25토픽, 12.6M/3.4M, ×25), C-G1 ②(토픽마다 분해 API ≤ 2), dev 민감도(코퍼스2에는 없음), 코퍼스2 판정(C-G2, FREEZE, assay, C-G6(a) 다리, C-H1~C-H5, 코퍼스1 정합) 추가. 실행: `python experiments/c2_analyze.py results/c2/heldout25 --rescore --corpus1 results/r2/heldout35 --negctl …`. 부트스트랩 topic × seed 2단, 10,000회, seed 42(R2와 같은 분석기 기본값, §8 표에 적음). seed별 점추정·부호표, 일원 랜덤효과 분산 성분. offline 재채점 = 루프 안 판정 100% assert.

| 가설 | 비교 | 지표 | 재현 조건 |
|---|---|---|---|
| **C-H1** | L-BR vs L-GR | 회계 토큰 절감 1 − ΣA/ΣB | 세 seed 부호 모두 양 ∧ 95% 하한 > 0 |
| **C-H2** | E-SQ vs E-GR | 같다 | 같다 |
| **C-H3** | E-SQ − E-GR | (a) 질의 legacy coverage, (b) 질의 MiniCheck grounding(0 규약) | (a)(b) 90% 하한 > −0.05. (b)는 C-G6(a) 통과 시에만 다리로 센다 |
| **C-H4** (E-R1 자동 다리) | E-R1 − E-GR | C-H3와 같다 | 같다 |

**검정 민감도(assay) 규칙 (C-H3·C-H4).** 전부 기권하는 가상 arm A0는 coverage·grounding(0 규약)이 0이다. 각 다리에서 **E-GR 값의 90% 하한 > δ(0.05)**가 아니면(즉 A0가 같은 검정을 통과할 수 있으면) 그 다리는 "판정 불가(민감도 부족)"다.

**2차(주장 조건 같음)**: C-H5 E-BR vs E-SQ 회계 토큰. branch-round·sub-question 실행 수 절감, 청구 토큰은 보고만.

**민감도**: grounding 짝 제외 읽기, δ ∈ {0.03, 0.10}, τ ∈ {0.7, 0.9}(offline), 토픽 1단 부트스트랩.

**판정 단어 (가설별, family-wise 오류 통제 없음, 결합 문장은 해당 가설을 모두 충족할 때만)**
- 절감: **재현**(R2와 같은 방향, 주장 조건 충족) / **방향만 일치**(점추정 같은 방향, 조건 미충족) / **재현 실패**(0 또는 반대; FREEZE 0으로 BR ≡ GR이면 여기, 원인 "sufficient branch 없음").
- 비열등: **재현**(센 다리 모두 통과) / **재현 실패**(하나라도 하한 ≤ −δ) / **판정 불가**(assay, 퇴화, G3).
- **코퍼스1과 정합**(별도 보고): (코퍼스2 − 코퍼스1)의 95% CI(두 코퍼스 독립 부트스트랩)가 0을 포함하고 점추정 방향이 같음. "방향만 일치"와 따로 적는다.

**원고 문장**

## 5. 순서, 블라인딩, 누출 통제, 일정

### 5.1 원칙

1. **A·B는 §3을 §2보다 먼저 한다**(시트 단계 잠금으로 강제하고, "3단계 시작" 뒤에는 1·2단계 답을 바꿀 수 없다 — §2.4). 저자 라벨이 피드백으로 나오는 §2 연습 **전에** §3을 끝내야 "저자 쪽으로 훈련된 판정자"라는 비판을 피한다. §3 보정 3문항의 저자 참조 C·K는 유일한 예외이고 공시한다.
2. **§2와 §3의 관문은 독립이다**(§3.6).
3. **논의 기반 조정은 없다.** §2는 기계적 다수결, §3은 조정 없음.
4. **저자 라벨은 모두 이미 커밋돼 있다**(§2.2 표, §3 보정 참조 라벨은 C1 전 커밋). A·B CSV는 받는 즉시 열지 않고 수정 없이 커밋한다.
5. **봉인 폴더**(`results/r3/sealed/`)는 채점 코드가 돌기 전까지 저자가 열지 않는다. 생성 스크립트는 문항별 arm·cell·라벨을 출력하지 않고 집계만 출력한다. 점검 문항은 출력 없이 봉인 키에 쓴다.
6. **코퍼스2는 무인으로 병렬 실행**한다. 그 결과는 A·B에게 보이지 않는다. §2·§3 규칙은 C0에 고정돼 있어 코퍼스2 결과가 영향을 줄 수 없다.
7. A·B는 서로 상의하지 않는다(첫 화면 안내, 감사의 글 동의는 교신저자가 받는다).

### 5.2 누가 무엇을 보는가

**A·B가 보는 것(전부)**: 한 HTML의 첫 화면 안내 → 1단계 보정 3문항과 참조 C·K → 2단계 품질 본 문항(피드백 없음) → 3단계 V′ 연습 10문항과 저자 라벨 → 4단계 V′ C50(피드백 없음). **보지 않는 것**: arm, 연산자 점수, cell, 가설, R2·코퍼스2 결과, 봉인 키, 서로의 라벨, C50 저자 라벨.
**저자가 보는 것**: 새 라벨을 달지 않는다(§3 보정 참조 3문항, §4 C2-V 40문장 제외). 채점 전에는 A·B CSV 내용과 봉인 키를 보지 않는다. 저자는 가설, R2 결과, §1.3의 집계를 이미 알고 있다(공시).
